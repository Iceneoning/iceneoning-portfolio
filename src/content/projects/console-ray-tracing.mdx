## 把固定字符画变成可以移动观察的画面

这是我刚接触图形学时做的小玩具。看着一行行字符在终端里拼成球体和倒影，再用键盘换个角度看看，当时觉得特别好玩。把它和这段录屏留在这里，也算是给刚开始学图形学的自己留个纪念。

两版程序都用同一组球体、棋盘面和键盘相机。基础版本以 121 × 101 个采样点绘制，逐行拼接字符串，每帧把光标移回左上角重写画面。改版的工作集中在采样尺寸、亮度到字符的映射，以及一帧如何交给 Windows 控制台显示。

## 每个字符格对应一条相机射线

窗口宽高决定本帧要计算多少个字符。渲染器取每格中心，将横纵坐标映射到 `[-1, 1]`，以相机前向、横向和竖向构造射线。纵向项乘上 `0.5` 的字符比例修正，因为终端字符格的宽和高通常不同。视角半角参与计算成像平面的宽度，所以键盘缩放会改变射线张开的范围。

球体求交相当于把射线 `P + tD` 代入球方程。程序用判别式判断是否有交点，并从各球体较近的正根里选最近的一项。向下的射线还会与 `z = 0` 平面求交。地面更近时，用交点两个平面坐标的奇偶组合选择棋盘亮格或暗格。球面更近时，累计亮度并从命中点继续计算反射。这里的亮度按传播距离衰减，便于在很少的场景元素里看清反射路径。

## 让暗部有层次，让整帧一起更新

基础版本使用九档灰度字符。改版先计算 `log1p(light) / log1p(1200)`，把结果限制在 0 到 1，再取字符表中最接近的一档。对数曲线让低亮度范围占到更多字符档位，暗球和倒影更容易区分，高亮也会在字符表上限收束。

显示端保留两个 Win32 控制台缓冲区。`WriteConsoleOutputCharacterA` 将本帧写到后台缓冲区，补写相机状态行后再调用 `SetConsoleActiveScreenBuffer`，下一帧换另一个缓冲区写。屏幕因此以整帧切换呈现。窗口越大，每帧要追踪的射线越多，动态分辨率与双缓冲分别影响渲染工作量和画面的提交方式。
