# 作品自动收录与首页精选维护

## 两个展示区域的职责

- **作品选集（自动）**：`src/pages/index.astro` 调用 `getPublishedProjects()`，读取 `src/content/projects/**/*.{md,mdx}` 中全部 `draft: false` 的项目。展映厅、作品数量、循环导航、卡片详情及项目详情路由都由集合生成；新增公开作品不需要改 `ProjectShowcase.astro`。
- **首页代表作品（手动）**：只编辑 `src/config/featured-projects.ts` 中的 `featuredProjectIds`，控制首页快捷入口的项目和排列顺序。它不影响作品选集收录与排序。该区域目前采用两个项目的布局，建议始终精选两项。

## 新增一部作品

1. 在 `src/content/projects/` 新建 `<slug>.mdx`，文件名即详情页路径的 `slug`，例如 `new-project.mdx` 会生成 `/projects/new-project/`。
2. 按 `src/content.config.ts` 定义的 Frontmatter 字段补齐标题、分类、摘要、标签、个人职责等内容，可参考现有 RTS / Blitz Archive 项目或 [技术案例标准模板](01-case-study-template.md)。
3. 整理素材时先使用 `draft: true`。完成真实性、授权、职责和链接核对后，改为 `draft: false`。
4. 设置唯一的 `order` 整数控制作品选集顺序。展映厅卡片和详情页将自动生成，项目计数会自动更新；无需手动编辑展映厅组件。
5. 如果要把该项目列为首页代表作，再手动修改 `src/config/featured-projects.ts` 的名单。只想出现在展映厅则不要修改该名单。

示例 Frontmatter（**仅是字段结构示例，不能作为真实项目成果发布**）：

```yaml
---
title: 待补项目标题
titleLines: [待补项目, 副标题]
posterCode: DEMO.
posterTitle: 待补海报标题
cardCaption: 待补简短职责
keywords: [UNREAL, C++]
tone: ice
subtitle: 待补项目一句话介绍
order: 3
engine: Unreal Engine
genre: Engineering Practice
role: 待核对个人职责
status: 开发中
summary: 待补完整的背景、目标及本人工作范围说明。
personalScope: [待核对个人职责]
integratedSystems: []
tags: [C++, Unreal Engine]
evidenceLevel: described
mediaApproved: false
draft: true
---
```

`mediaApproved: false` 时，卡片使用现有通用概念插画，并明确标注非 UE 实机画面。取得可公开且经过核实的实际项目图片后，可填写 `cover` 和 `coverAlt`，并将 `mediaApproved` 改为 `true`；封面路径需能从站点访问，禁止将概念图标成实机画面。

## 验收

在项目根目录执行：

```bash
pnpm run check
pnpm run build
pnpm run verify:build
```

静态回归脚本按实际公开详情页数量验证展映厅和相邻项目导航，不再以固定两部作品为前提。项目内容更新后仍须在浏览器内确认图片、透视卡片和触摸/滚轮行为。
